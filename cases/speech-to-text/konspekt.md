# Чат-бот с базой знаний для Битрикс24: поддержка клиентов и адаптация (Подпислон AI-агенты)

Разбор двух сценариев чат-бота с векторной базой знаний (БЗ) для Битрикс24 на сервисе «Подпислон Агенты»: бот для сотрудников (онбординг по внутренней БЗ) и бот для клиентов на сайте (продуктовая БЗ, открытые линии).

## Векторная база знаний (как работает RAG)

Обычный поиск ищет по словам, векторный — по смыслу.

1. Текст режут на куски (чанки): абзацы, страницы, фрагменты документации.
2. Каждый чанк прогоняют через модель эмбеддингов, получают вектор — массив чисел, «координаты смысла».
3. Векторы кладут в базу.
4. Запрос пользователя тоже превращают в вектор.
5. База ищет ближайшие по смыслу векторы и отдаёт соответствующие куски текста.

В контекст ИИ передают не весь объём данных, а только наиболее близкие по смыслу фрагменты.

## Загрузка базы знаний в «Подпислон Агенты»

Сценарий загрузки — из трёх нод:

1. Ручной запуск.
2. Загрузка документа: прикрепляем БЗ, указываем размер чанка (подбираем примерно под куски, на которые разбита БЗ).
3. Передача чанков в модель эмбеддингов: указываем название коллекции (используем его далее в чат-боте), операцию «индексация» и выбираем модель.

Для внутренней БЗ — модель от Яндекса, чтобы данные хранились в РФ.

Правила подготовки документа БЗ:

- Формируем документ с информацией по теме, в которой должен разбираться бот.
- Заранее разбиваем его на примерно одинаковые куски, разделённые спец-символом.
- Тогда модель всегда получает на вход цельный кусок по одной теме.

### Пример структуры внутренней БЗ

Документ «Внутренняя база знаний компании», версия 1.0, владелец — HR-отдел. Разбит на разделы:

1. Общие положения (заявки оформляются в Битрикс24, рабочий день 10:00–19:00 МСК).
2. Рабочее время и удалённая работа (гибкое начало, удалёнка до 8 рабочих дней в месяц, переработки — отгулом).
3. Отпуска (ежегодный 28 календарных дней, аванс в первый год, перенос, отпуск за свой счёт до 14 дней).
4. Больничный и отсутствие по здоровью.

## Сценарий 1. Чат-бот для сотрудников (внутренняя БЗ)

### Логика процесса

- **Триггер** — входящий HTTP-запрос от бота.
- **Развилка по событию:**
  - пользователь присоединился к чату → выводим служебное сообщение (пользователю ничего не отправляем);
  - пользователю нужен ответ → идём дальше.
- **Поиск по БЗ:** та же модель эмбеддингов, что при индексации, но операция «поиск»; та же коллекция; в запрос передаём сообщение из веб-хука.
  - Порог релевантности: для маленькой тестовой БЗ — 0,2; при ~1000 хорошо разбитых чанков можно 0,5. Подбирается опытным путём.
- **ИИ-ассистент:** модель того же вендора, что и для эмбеддингов. Системный промт — роль бота, источник данных, цели. В промт передаём имя сотрудника и вопрос (вопрос дублируется и в запрос к БЗ, и к ИИ).
- **Условие эскалации:** в инструкции модели задано — если ответить по БЗ нельзя, вернуть определённый набор символов (кодовую фразу). Этот набор проверяем в ноде условия.
  - не ответил → создаём задачу на сотрудника другого отдела + информируем пользователя в чате;
  - ответил → отдаём ответ пользователю.

### Подключение Битрикс24

1. Битрикс24 → раздел **«Разработчикам»** → «Добавить чат-бот».
2. Выбираем вариант **«Передавать боту сообщения из чата»** (бот следит за перепиской и реагирует).
3. Заполняем название бота; копируем показанный веб-хук (понадобится в Подпислон).
4. Тип чат-бота оставляем как есть, убираем галочку исходящего веб-хука.
5. Права: чаты и уведомления; создание и управление чат-ботами; задачи (нужны для постановки задач).
6. В Подпислон на вкладке «Битрикс24» создаём подключение, указываем его в нодах постановки задачи и ответа в чат.

### Переменная Bot ID

- Для бота Bot ID фиксированный — задаём один раз в переменной процесса.
- Найти ID: после первого запуска → вкладка **«История запусков»** → событие чат-бота Bitrix24 → раздел `out` → `DataBot` → ID бота.
- Подставляем значение в ноды ответа в чат сотрудника.

### Демонстрация

- Высокий порог релевантности → бот не смог ответить.
- Порог 0,2 → ответил прямо по БЗ.
- Несвязное сообщение → «в базе знаний информации нет», просит уточнить.
- Связный вопрос без ответа в БЗ → создаёт задачу, сообщает «передал вопрос коллегам» и указывает ID задачи. В задаче указаны сотрудник, диалог, вопрос и вердикт ассистента о переводе на другой отдел.

## Сценарий 2. Чат-бот для клиентов (продуктовая БЗ, открытые линии)

### Логика процесса

- **Триггер** забирает веб-хук, с которым идём в Битрикс настраивать бота.
- **Развилка по событию** (Битрикс присылает присоединение к чату и сообщение):
  - присоединение → приветствие в чат («Привет, я консультант по вопросам клиента»); указываем Bot ID, ID диалога, Client ID;
  - сообщение → поиск по БЗ.
- **Поиск по БЗ:** другая коллекция и другая модель эмбеддингов. БЗ по продукту открытая — можно передавать за границу. Порог релевантности выше, т.к. БЗ наполнена качественнее.
- **ИИ-ассистент:** передаём найденные куски + вопрос + промт; роль ассистента, базовые инструкции, имя и фамилия клиента, вопрос.
- **Кодовая фраза эскалации** разводит процесс на две ветки:
  - ответ клиенту по БЗ (через готовую ноду из списка интеграций);
  - перевод на оператора.

### Перевод на оператора (HTTP-запрос)

Тело запроса:

- `CHAT_ID` — из данных триггера;
- `TRANSFER_ID` — `queue`;
- `LEAVE` — `Y`;
- `CLIENT_ID` — из запроса.

Веб-хук берём из переменных. Метод (`imopenlines.bot.session...`) — из документации Битрикс24 или копируется из видео.

### Создание бота в Битрикс24

- Метод создания тот же, но **тип — «Чат-бот для Открытых линий»** (бот используется в виджете на сайте).
- Права: служба сообщений; чат-уведомления; создание и управление чат-ботами; открытые линии.
- После создания копируем веб-хук в подключения и задаём переменную процесса.

### Настройка открытой линии

1. Контакт-центр → создать открытую линию + онлайн-чат для сайта.
2. Получаем публичную ссылку на чат.
3. В настройках открытой линии → раздел «Чат-боты» → указываем нашего бота.
4. «Через какое время переводить разговор в очередь» → **не переводить** (управление переводом реализовано в процессе).

### Демонстрация

- При входе бот присылает приветствие.
- На вопрос по БЗ отвечает по данным, не выдумывая.
- На «Переведи на оператора» распознаёт намерение, уходит в ветку перевода, пишет «подключаю менеджера», диалог переводится.

## Итог

Разобраны два распространённых сценария: чат-бот для онбординга сотрудников и чат-бот для клиентов, отвечающий в нерабочее время вместо менеджеров. Создавать ботов под свои задачи можно самостоятельно в сервисе «Подпислон Агенты».
